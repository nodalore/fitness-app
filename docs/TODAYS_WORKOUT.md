# Today's Workout — current status

Updated 2026-10-18. Saving, resuming and finishing are implemented and tested locally. **Hosted saving is pending separate review/application of migration 008 and live test-account acceptance.** Migrations 001–007 are installed per the user; 008 is not applied. My routines separates Today's Workout from Saved routines. Choose an active saved routine and a named Day/session explicitly; there is no weekday assignment. Saved recommendation copies and completely custom plans work alike. Only one exercise expands at a time, with compact Set / Weight / Reps rows. Add set explicitly records performed work; no Done checkbox, planned-set initialization, copied actual targets or exercise photos exist.

The workout owns independent actuals and snapshots. Free-text/catalog substitutions, added exercises, skips and removals affect only that workout. Removing a set deletes that incorrect actual row. Removed/skipped exercises retain workout-specific metadata, while counts exclude them. A replacement starts with zero actual sets and keeps original name/target provenance. Kg/lb values remain per-set; actual zero and unspecified weight remain distinct.

The application now uses a serialized, debounced autosave queue with stable entity/request IDs, revision conflicts, bounded network waits, account-scoped unsent-change recovery and explicit save indicators/errors. Unfinished workouts can be resumed after reload/sign-in once hosted 008 is installed. Pending exercise composer input must be added or cancelled before choosing another session/finishing. Finish validates included reps and applicable weight, confirms a summary, and permanently completes the same session exactly once. Partial workouts are allowed; a zero-set completion is rejected.

`workoutDraft.ts` and the Stage 3 read adapter retain the real routine/day IDs, exact routine version, names, original prescription snapshots and independent actual IDs/values. The save RPC never updates planned routines or the catalog. Source-routine edits/history protection and authenticated ownership remain intact. A separately confirmed independent snapshot recovery handles a source changed before initial save without guessing foreign keys.
